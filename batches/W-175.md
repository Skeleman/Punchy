# W-175 (Zach 11-15): placed units as hierarchies of standalone parts

Issue #415. Lane: materials (after W-166 row 2), since both give every thing one definition. Shares (rule 33): W-166
material library, StructureKit, #399 (every building from kit pieces, W-173 row 3).
Zach's aim: a blacksmith tent or vendor stall is a composite of standalone parts (awning, table, anvil, crates, sign).
Each part is defined once, units list their parts, other units reuse them, and a change to the anvil reaches every anvil.

## Row 1: audit and proposal (no code; stop for Zach's OK)

- Propose one part definition (mesh builder + material kind from W-166 + collider + optional use, such as an anvil

## Rows 4-6: kit gaps found by the Lab blueprint editor (M-06 r5, PR #469; full list in REPORTS-animal 11-16)
- **Row 4: part format fixes (no look change).** Per-part rotation and mirror (the door mat only faces +Z). Sizes in
  metres, with the host and size stored in the JSON and floats rounded (0.699999988). One size rule for every part: the
  pyramid roof's Span is a half-size; the fire ring and embers take their radius from Span.y and ignore At. Parts stop
  overwriting the unit's bounds (fire ring, hide tent). Each part gets its own random stream so order doesn't matter.
  The coded units must keep their W175Probe hashes.
- **Row 5: missing parts, each with a W-166 material kind and a collider.** Walls, floors, doors and windows (with a
  facing direction; player needs door and floor colliders), gabled roof, beams, stairs, rails, signs, lanterns, crates.
  Lanterns and crates join r3b's kit adapter, not a second copy (rule 33).
- **Row 6: composition.** A unit can hold another unit; parts snap at their joins. World placement reads
  FloraSpecies.Unit and JSON units at runtime (rule 22 world file), so a Lab blueprint can be placed in a town.
