## Row 3b: save a new creature and pick the biomes that own it (Zach 11-15, #413)
- A "Save as new creature" button names the edit and writes it as a new species entry in the same species data the
  game reads (no Lab-only format). It is appended after the existing species so their ids and blob bytes stay put.
- The save also lists the biomes that own it (checkboxes from the biome list, with a rough share per biome). The
  game's biome spawn tables read that list, so the new creature spawns in those biomes with no code change. One
  system (rule 33): built-in species carry the same biome list, so later edits use the same field.
- Spawn tables are fauna code: if they can't read a per-species biome list yet, report the smallest data hook and
  stop; the supervisor routes it to fauna. Appending a species is network-visible (rule 11): appending at the end is
  pre-approved; anything that reorders or renumbers species is not. Expect a Fauna_Fingerprint re-pin for the added
  species only; untouched species must bake identical.
- Check: save a test creature owned by one biome, -goto that biome, see it spawn there and nowhere else, and see it on
  a joined client. Shot: the Lab save panel and the creature in its biome.
